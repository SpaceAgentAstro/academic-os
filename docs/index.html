What it is

Retrieval before generation, always.

An autonomous educational intelligence platform built for one student studying five subjects at once. It does not invent questions and it does not advance you automatically. It retrieves what real examiners actually wrote, and builds revision from it.

Ingestion & OCR

Past papers parsed into structured questions with marks, topics, and diagrams — pdfplumber with an OCR fallback for scanned pages.

Mark schemes

Real mark-scheme points — M/A/B/E marks, alternatives, required terms, follow-through — matched to each question by exam code and date.

Examiner intelligence

Examiner reports mined for recurring misconceptions, so the traps real students fall into are surfaced before you sit the paper.

Adaptive mastery

Every marked attempt updates mastery and a spaced-repetition interval per spec point: strong work pushes reviews out, weak work pulls them in.

Honest dashboard

Coverage, weaknesses, predicted grades — every figure from a live SQLite query. When data does not exist yet, the screen says so. It never fabricates.

Daily briefing

A retrieval-first morning briefing — due reviews, examiner traps, a question of the day — generated from exactly what you practiced.

The Standard

One loop, end to end, on real data.

The acceptance bar from context.md: practice a real paper and watch your mastery move. Verified on WPH14 — Physics Unit 4, June 2024.

  1. Open the app and pick a real paper.WPH14 June 2024, loaded from question_bank.db
  2. Start the timer — a real session is created.POST /api/sessions → row in analytics.db
  3. Work the questions — real times are logged per question.PATCH per question, official vs. target time tracked
  4. Go to marking — the real mark scheme appears.M/A/B points pulled live from markscheme.db
  5. Award marks — the attempt is saved.marks, confidence and mistake tags persisted
  6. Watch the dashboard update — mastery actually changes.21 Physics spec points updated in progress.db
  7. Review what moved — coverage, weaknesses and the next due review reflect today.
✓ Verified working — a full WPH14 run produced an 80% aggregate across sessions, logged per-question times, saved every marked attempt, and updated 21 spec points' mastery and spaced-repetition state. The Telegram delivery channel is intentionally out of scope for this build.

Architecture

Local-first. One database per domain.

Everything runs on the student's own machine. No cloud sync, no external database server — SQLite files, a FastAPI backend, and a Next.js front end.

Stack

Front endNext.js · TypeScript · Tailwind
BackendFastAPI · Python 3.11+ · uvicorn
StorageSQLite — one file per domain
OCRpdfplumber · pytesseract
SchedulingAPScheduler

Databases

question_bank.dbpapers, questions
markscheme.dbmark-scheme points
examiner_reports.dbobservations, misconceptions
progress.dbmastery, spaced repetition
analytics.dbsessions, attempts, times
Agent ownership is strict: the Curriculum Agent is the sole authority for syllabus progression — no other agent writes syllabus state. Architecture precedes implementation; generation is the last resort, behind retrieval.

Run it

Clone, serve, practice.

Academic OS is a local application — this page is its home, not the app itself, because the app needs its FastAPI backend and your own databases running on your machine. 

# 1 · clone
git clone https://github.com/SpaceAgentAstro/academic-os
cd academic-os

# 2 · backend (FastAPI on :8000)
DATA_DIR=./data uvicorn backend.main:app --port 8000

# 3 · front end (Next.js on :3000)
cd frontend && npm install && npm run dev

# 4 · open the app and run The Standard
open http://localhost:3000
First run? Seed the syllabus and run the extraction pipelines in scripts/ to populate the mark-scheme and examiner databases. Full setup notes live in RESTART.md and CLAUDE.md.
